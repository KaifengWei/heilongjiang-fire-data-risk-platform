## 1 简介

农业秸秆焚烧区域火点检测与分析平台是一款面向农业相关区域 FIRMS 火点观测分析的 Windows 桌面软件。使用者导入 NASA FIRMS 主动火点 CSV 文件后，软件完成文件识别、基础质量检查、有效观测整理和时空统计，生成与该批数据对应的分析任务。结果页面结合日期变化、空间集中区域、跨日重复观测、土地覆盖及适用的天气资料，提炼本次火点活动中值得关注的区域与时间信息，并支持导出 Word 图文报告。

### 1.1 编写目的

本文档说明软件的运行环境、数据准备、分析操作、结果查看、记录管理和 Word 报告导出过程。使用者可按照文中步骤完成从 FIRMS CSV 导入到结果保存的完整工作流程。本文档同时为 Windows 实机验收、功能核对和软件著作权材料整理提供操作依据。

### 1.2 使用对象

本软件适用于农业科研、火点观测数据整理、农业生产区域环境分析等工作中需要对主动火点记录进行统计、比较与结果复核的用户。使用者应能够完成 Windows 文件选择、CSV 文件管理和普通桌面软件操作。

### 1.3 应用场景

FIRMS CSV 通常包含观测时间、经纬度、卫星及仪器信息等字段。对于跨日期、跨空间范围的观测数据，单独查看记录表不利于迅速判断火点何时集中出现、主要分布在哪里，以及哪些局部位置在不同日期重复被观测。软件以独立分析任务为单位组织这些结果，帮助使用者从原始数据中提取时间、空间和地表方面的信息，形成可查看、可导出、可再次打开的记录。

## 2 产品概述

### 2.1 运行方式与技术组成

软件采用 Python 编写主要数据处理和业务逻辑，通过 Flask 提供本机业务服务，由 pywebview 在独立的 Windows 窗口中展示界面。程序使用 HTML、CSS、JavaScript 组织页面及地图交互，SQLite 保存本地任务与结构化记录，GDAL、PROJ、Shapely 等组件用于空间数据处理，python-docx 用于生成 Word 报告。

正式桌面版本采用 PyInstaller onedir 方式构建。完整程序包括 EXE 文件及其随附运行目录，用户使用发布包时应保留全部运行文件。软件采用 Windows 用户级目录保存数据库、上传记录与运行缓存，使其与可执行程序分开存放。

本软件的正式交付形态为 Windows 桌面端；开发过程中使用的本地页面不作为单独互联网服务交付。

### 2.2 数据类型与用途

| 数据或组件 | 当前作用 | 软件中的表现 |
| --- | --- | --- |
| NASA FIRMS 主动火点 CSV | 本次分析的主要输入；识别观测日期、经纬度、数据来源并完成质量处理 | 有效观测数量、时序变化、真实点位和重点网格 |
| MCD12Q1 2024 土地覆盖 | 在已安装的栅格覆盖范围内，对真实观测点采样土地覆盖类别 | 已匹配比例、耕地及混合植被背景、其他地表类别及样点分类栅格 |
| 有来源的农事时段规则（JSON） | 按用户安装的具体地区、作物和月份规则补充农业活动背景 | 匹配到规则时显示相应相关性依据 |
| FIRMS 历史基线 | 在任务时间与地区有可比较资料时分析同期差异 | 同期变化与相对重点区域 |
| NASA POWER Daily | 历史任务期间的气温、湿度、风速和降水资料 | 任务期天气、高值日气象差异与逐日对照 |
| NOAA GFS | 对符合近期条件的任务提供 24、48、72 小时气象背景 | 相应时效的气象信息和关注提示 |
| GeoJSON 区域边界 / 离线底图 | 用户按需安装，辅助边界落区或地图轮廓查看 | 精确边界模式、地图底图和区域定位 |

FIRMS CSV 为标准工作流程的必要输入；地区名称和经纬度矩形为选填。行政区边界属于高级功能，土地覆盖、历史同期与天气资料根据当前数据范围及资源状态提供相应结果，不作为创建普通分析任务的前置条件。

### 2.3 系统功能组成

| 功能入口 | 工作内容 |
| --- | --- |
| 首页 | 显示软件定位、主要分析能力及“开始分析”“分析记录”入口 |
| 开始分析 | 选择 FIRMS CSV、预览观测范围、填写选填区域信息并发起分析 |
| 数据教程 | 显示 FIRMS CSV 获取、下载及导入说明 |
| 分析记录 | 列出本地保存任务，支持打开结果、重命名及移除记录 |
| 分析结果 | 展示本次有效观测、日期变化、地表构成、地图、重点网格、天气和可操作的查看建议 |
| Word 报告 | 将当前任务的分析数据、图表及适用的天气与地表内容生成 DOCX |

### 2.4 分析流程

软件对每次上传建立独立任务。处理流程依次为：读取并验证 CSV、识别实际观测日期和位置、质量筛选及去重、应用用户指定的可选范围、统计时间与空间特征、匹配可用的地表与历史资料、展示结果及按需获取天气，最后生成报告与保存任务记录。用户在后续打开同一条记录时，可以继续查看其已有结果与关联数据。

### 2.5 结果判读范围

软件中显示的火点数量为满足当前处理规则的主动火点观测条数，不能直接作为独立起火事件数。土地覆盖比例指成功匹配到栅格的火点观测构成，而非研究区域面积构成；跨日重复表示同一统计网格在不同日期出现观测。软件提供的关注程度及建议服务于对实际观测变化的解释，不输出火灾发生概率。

## 3 使用说明

### 3.1 启动软件与认识主界面

将发布 ZIP 解压至本地文件夹，保持程序 EXE 与 \`_internal\` 等运行资源完整。双击“农业秸秆焚烧区域火点检测与分析平台.exe”启动桌面程序。窗口左侧为功能导航，右侧为相应工作页面。默认显示独立首页；通过“开始分析”进入上传流程，通过“分析记录”打开此前保存的任务。

“分析结果”入口与当前选中的任务关联。尚未形成当前任务时，入口处于不可用状态；成功分析或从记录中打开一条任务后，该入口用于返回对应结果页面。

### 3.2 准备 FIRMS CSV 数据

使用者从 NASA FIRMS 数据提供页面获取符合其研究需求的主动火点数据，选择 CSV 格式下载并完成解压。在 Windows 中确认文件后缀为 \`.csv\`，准备在分析页面选取。软件主要面向 FIRMS CSV；普通分析页面不要求先安装地区边界或手动指定卫星及仪器。

左侧“数据教程”和分析页面中的相应按钮可打开 CSV 获取与上传操作说明。若文件缺失必要字段、文件格式不符合要求或无法形成有效观测，页面会提示对应原因。

【待插入实际 EXE 截图：教程弹窗与 CSV 选择控件】

### 3.3 开始一次新的火点分析

单击“开始分析”，在“上传数据”区域选择一个或多个 FIRMS CSV 文件，也可以使用拖动上传方式。程序自动识别数据时间范围与相关字段，并将本次输入作为新的分析任务。

“本次分析区域名称”仅用于标记任务，可留空，不会作为已经核实的行政归属。需要进一步筛选 CSV 时，可在“按经纬度矩形筛选”中填写西、南、东、北四个值，例如 \`110,30,113,33\`。填写该选项后，软件仅统计矩形内符合处理规则的观测。可先单击“查看 CSV 观测范围”读取实际点位跨度，再决定是否填写筛选矩形。

“高级设置”中可选择地区边界精确匹配。该方式需要有来源且符合要求的 GeoJSON 边界数据，适用于确实需要按边界筛选的场景。农事时段规则同样属于按需安装的高级资料；没有配置规则时，仍可分析实际已匹配的耕地背景。

确定数据文件及参数后，单击“开始区域火点分析”。任务完成后进入当前分析结果页面。

### 3.4 查看本次观测概览

结果页面顶部显示任务名称、分析日期区间和有效火点观测数量。坐标任务会呈现观测日期数、经纬分组数及火点日期变化图，并以实际 CSV 统计显示本次观测最突出的日期和位置。

对于土地覆盖，页面以样本匹配率表示当前 MCD12Q1 2024 资源匹配到多少条观测，区分已匹配和未匹配记录。农业相关性模块以成功匹配的观测数为基数，展示耕地及混合植被、其他地表背景的构成。系统可在数据允许时选取真实观测坐标，在分类栅格中截取周围像元作为样本图；样本图表示地表分类，不是真彩色光学照片。

### 3.5 使用空间地图与日期交互

地图工作区以真实观测经纬度绘制火点，可以通过拖动平移、Ctrl 加滚轮以及界面中的加减按钮进行缩放。必要时使用“查看底图全貌”恢复完整观察范围；已安装来源明确的 GeoJSON 离线底图时，可辅助查看地区轮廓。没有可用行政轮廓的情况下，仍可依据 CSV 中的真实坐标显示观测点。

地图旁展示经纬度位置分组。日期筛选和高值日快捷按钮可切换观测日；“当前情况与建议”中的位置与日期按钮可联动地图定位至对应网格。空间重点使用观测网格统计结果，不将该网格等同于具体农田地块。

### 3.6 解读空间集中、日期高值和跨日重复结果

“当前情况与建议”围绕三个可操作问题组织：先看哪里、先看哪一天，以及哪些位置在多个日期重复出现。

空间卡展示累计观测最集中网格的实际数量，并可点击定位；日期卡显示火点最多的日期及当日主要集中网格，可切换至该日地图；跨日卡依据同一局部网格在不同观测日期出现的记录，提供重复观测位置查看入口。若没有形成符合条件的跨日重复位置，页面不应虚构重复数量。

“观测最多的三个网格”展示前三个统计网格的火点数量和出现日期；可展开查看样点坐标、日期与地表对应信息。用户可以据此区分累计热点与单日热点是否位于同一位置。

### 3.7 查看历史同期与天气信息

当任务具备可比较的历史 FIRMS 数据时，页面显示历史同期变化及重点地区排序。历史参照来源、窗口及结果按当前任务可用数据生成，不将历史数据套用于不对应的区域。

天气模块根据任务时段使用相应资料。历史任务采用 NASA POWER Daily，展示任务期平均气温、湿度、风速、降水，比较火点增多日期与任务期的气象差异，并提供按日期的火点数量和天气变化图。符合近期时效的任务采用 NOAA GFS，展示可用的 24、48、72 小时天气背景。取样点与本次实际观测空间位置关联。

在历史任务的联合分析中，用户可进一步查看高值日天气、热点网格与取样位置、相应土地覆盖分类的对应证据；详细口径与逐日数据可按需展开。

打开左侧“分析记录”，页面展示已完成任务的名称、日期范围、有效火点数量、分析时间和操作入口。单击“查看结果”可重新打开对应任务；单击“重命名”可以调整记录标题；“删除”用于从记录管理界面移除相应任务，具体文件保留策略以程序实际持久化机制为准，不能将此操作直接理解为对本机全部原始数据的永久清除。

### 3.9 导出 Word 图文报告

打开已完成的分析任务，在结果页右上角单击“导出分析报告”。桌面程序将当前任务的统计结果生成 DOCX 文件并通过系统下载流程保存，使用者可在 Word 中继续检查、编辑或归档。

报告以实际任务观测为依据，包含总体观测情况、时间分布、空间位置与重点网格、可用的地表及天气资料等内容。对于足够长的任务日期区间，报告可以插入火点日期趋势图；在取得对应空间信息时，可插入分析地图与网格证据；对于已取得历史天气的任务，可提供火点日期与每日天气对照。报告图表与数据取自该任务对应的记录，不使用其他任务的图形填充。

## 4 数据管理与结果使用

### 4.1 本地记录与文件保存

桌面端采用 SQLite 保存任务及观测相关数据，用户上传的文件和运行缓存存放于当前 Windows 用户本地目录。完整发布包用于运行程序，本地用户目录用于保存分析任务和对应资源。更换发布包时应保留此前的用户数据位置；若移动整个程序到其他目录，也不应直接清空既有运行目录。

### 4.2 输入数据与结果追溯

每条任务对应独立的输入文件、处理参数和分析时段。结果中的数量、日期、空间网格与天气资料应能够追溯到同一任务。对于截图中出现的数值，应以保存的原始 CSV、任务记录和数据来源为基准复核；若修改筛选范围，应将其视为另一组分析条件，而非直接与原任务数字混用。

### 4.3 地表和天气信息的适用条件

MCD12Q1 分类图、历史同期分析、农事规则及天气结果使用各自实际可得的资料。地表只对成功匹配到的观测点提供类别；天气分析显示对应任务范围和代表点取得的气象背景。用户可以在结果页展开查看样本位置、来源及统计口径。

### 4.4 报告管理与导出结果核对

每次导出 DOCX 后，应检查报告任务名称、日期区间、总观测数、热点网格和实际天气是否与结果页一致，并核对中文字体、图片、表格跨页和文件保存位置。软件的源程序自动测试不能替代用户在 Microsoft Word 中的实际分页检查。

### 4.5 软件发布与数据备份

软件发布采用包含 EXE 和运行依赖目录的完整压缩包。程序安装或更新后，可以利用“分析记录”确认旧任务是否仍能打开。在迁移 Windows 账户、重装系统或更换计算机前，使用者应先备份对应的用户数据目录和需要保留的原始 CSV。

### 4.6 主要使用注意事项

应优先使用来源明确、字段完整的 FIRMS CSV。统计分析表达的是主动火点观测及其空间、日期特征。分析区域标签是用户自行命名的记录标记，不能代替经过验证的区域边界。若需要严格的行政区归属，应使用真实且适用的边界数据；若需要地表或历史同期判断，应确认其数据覆盖范围与本次任务一致。
