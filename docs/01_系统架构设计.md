# 农业秸秆焚烧区域火点检测与分析平台 — 当前系统架构

> 此文件描述正在交付的 Windows V1.0 桌面程序，不把早期规划中的模块当作已交付功能。

## 1. 桌面运行架构

软件通过 \`src/fire_monitor/desktop.py\` 在 Windows 桌面创建 pywebview 窗口，内部启动绑定 \`127.0.0.1\` 的本地 Flask/Werkzeug 服务。数据分析及页面路由在同一台计算机上执行。程序没有依赖远端数据库服务器或公共部署网站，网络仅供需要的外部气象数据服务访问。

主要组成如下：

| 层级 | 代码范围 | 实际职责 |
| --- | --- | --- |
| 桌面入口 | \`desktop.py\`、\`src/fire_monitor/desktop.py\` | 创建可调整大小的窗口、启动/停止本地服务 |
| 路由与页面 | \`src/fire_monitor/app.py\`、\`templates/\`、\`static/\` | CSV 上传、任务路由、结果展示、地图与交互 |
| 业务层 | \`src/fire_monitor/services/\` | 自动分析、地表/天气/历史资料、任务保存、报告生成 |
| 基础处理 | \`src/fire_monitor/core/\` | FIRMS 解析、字段与空间数据校验、统计所需处理 |
| 数据持久化 | \`src/fire_monitor/storage/\`、\`src/fire_monitor/user_data_paths.py\` | SQLite 数据库、输入文件关联及用户目录 |
| Windows 打包 | \`fire_monitor.spec\`、\`scripts/finalize_windows_delivery.ps1\` | onedir 构建、运行依赖自检、ZIP 完整性与验收清单 |

## 2. 主业务数据流

用户选择 NASA FIRMS CSV 后，\`AutoAnalysisService\` 识别文件和日期并创建任务，\`FirmsProcessingService\` 完成实际观测规范化、质量处理和入库。随后结果页面从保存任务获取统一的观测数据，组织时间变化、网格分组、空间定位及重点日期。

普通模式以 CSV 自带的真实坐标为基础，区域标签仅记录用户声明；用户选填矩形时才执行矩形筛选。高级边界模式对已配置 GeoJSON 执行匹配。地图由 \`static/product.js\` 和 Canvas 配合数据接口绘制，结果页布局使用 \`templates/task_detail.html\` 以及 \`static/product.css\`、\`static/result_console.css\`。

## 3. 数据证据组件

- \`LandCoverContextService\` 读取已安装的 MCD12Q1 2024 分类栅格，在真实火点位置采样；\`land_cover_visual_service.py\` 在类别与观测点匹配一致时生成周边分类像元样本图。
- \`agricultural_relevance_service.py\` 汇总已匹配的地表分类、耕地及混合植被证据；可选择结合来源明确的农事时段规则。
- \`observation_decision_service.py\` 将实际火点整理为集中网格、高值日位置、重复观测位置及前三网格比较。
- \`historical_weather_context_service.py\` 获取历史任务的 NASA POWER Daily；\`gfs_weather_context_service.py\` 获取符合条件的近期 NOAA GFS 24/48/72 小时背景。
- \`weather_observation_synthesis_service.py\` 在资料可用时将历史天气与实际火点日期、空间网格、土地覆盖结果对应展示。

历史资料、气象数据和地表栅格并非全部任务都必然具有相同覆盖范围；页面和报告按实际取得的数据提供内容。

## 4. 报告与图表

\`report_docx_service.py\` 通过 python-docx 生成当前分析任务的 DOCX 文件，汇总观测数量、日期、空间重点、农业地表背景及可用天气。地图和日期走势图由空间报告和时间线模块提供，报告输入来自当前任务的统一观测数据。Windows 桌面模式开启文件下载支持，用户在结果页发起 Word 导出。

## 5. 数据目录与版本

桌面运行时使用 Windows 用户级本地应用数据位置，保存 SQLite、上传文件、离线地图与缓存等。历史用户数据目录名称保留兼容性，以免因程序重命名丢失已有记录。程序可执行文件与用户数据分离，更新 onedir 发布包无需更改用户数据位置。

代码在原 GitHub 仓库的 \`feature/regional-ui-consolidation-v1\` 分支持续维护。针对 Windows 交付，\`scripts/build_and_check_exe.ps1\` 和 \`scripts/finalize_windows_delivery.ps1\` 分别执行编译检查与最终 ZIP 核验，并形成版本绑定的实机验收清单。

## 6. 自动测试与实机核对

主要 API、数据处理、地表分类、气象比较、报告图表、地图响应与发布脚本设有自动化回归测试。测试成功表明代码路径满足相应断言，不能代替 Windows 图形窗口、实际任务数据与 Word 分页的最终确认。当前用户说明与提交材料以 [软件使用说明候选稿](SOFTWARE_MANUAL_V1_DRAFT.md)、[软著信息采集表](SOFTWARE_REGISTRATION_FORM_DRAFT.md)为准，具体证据与验收要求参见 [交付手册](DELIVERY_HANDOFF.md)。
