# 开源发布与数据合规清单

远程 GitHub 仓库建立前逐项确认：

## 1. 密钥与隐私

- [ ] `FIRMS_MAP_KEY` 仅保存在本机环境变量或未提交的 `.env` 文件；
- [ ] 使用 `git grep -n -i "map_key\|api_key\|token\|password"` 检查历史和当前代码；
- [ ] 不上传个人电脑绝对路径、聊天截图、账号信息或不可公开的单位资料；
- [ ] 不在 README、Issue、截图或演示视频中展示真实 MAP_KEY。

## 2. 数据与许可

- [ ] 核实 FIRMS 数据使用说明和引用要求；
- [ ] 核实行政区边界数据的来源、版本、下载日期和再分发许可；
- [ ] 原始 TIF、Shapefile、数据库和完整下载 CSV 默认不随代码仓库上传；
- [ ] 如需示例数据，仅提供规模很小、来源明确、可再分发的样本，或提供下载脚本；
- [ ] 在 README 中写清数据来源、时间范围、空间范围与质量筛选规则。

## 3. 代码可复现

- [ ] 在一台未配置原始路径的电脑上按 README 新建环境；
- [ ] 导入一份公开/可用的边界、FIRMS CSV 和 MCD64 TIF；
- [ ] 运行 `pytest`；
- [ ] 启动页面并核对三张统计卡片、地图图层、逐日表和 CSV 导出；
- [ ] 将验证所用的命令、版本和已知限制写入 Release Notes。

## 4. 软著资料一致性

- [ ] 使用 `03_软著功能与源代码对应表.md` 逐项核对功能说明；
- [ ] 软件截图来自实际运行页面；
- [ ] 源程序页按当前版本导出，保留文件名和页码；
- [ ] 用户手册只介绍当前能实际操作的按钮、命令和结果；
- [ ] 未来功能明确标为“规划”，不混入已实现功能。

## 5. 发布顺序建议

1. 完成当前 v0.1 的真实数据复算与界面验收；
2. 选择许可证（MIT、Apache-2.0 或由学校/单位确认的许可证）；
3. 在本地初始化 Git、提交无密钥且可运行的代码；
4. 新建 GitHub 仓库并推送；
5. 创建 `v0.1.0` Release，附环境、数据说明与已知限制；
6. 再据此整理软著源代码、说明书和运行截图。
