# 黑龙江省火点数据检测与风险评估平台

## 项目范围与功能边界

### 1. 项目名称

黑龙江省火点数据检测与风险评估平台。

### 2. 项目定位

本软件是一套面向黑龙江省区域遥感火情数据处理与分析的本地化软件平台。

平台面向用户自行获取的遥感火情数据，对 FIRMS 主动火点数据以及 MCD64A1 火烧迹地数据进行导入、校验、规范化处理、统计分析、空间制图和结果追溯，并在明确的数据范围和评价规则下提供遥感火情关注程度或规则型风险评价结果。

软件主要用于遥感火情数据整理、分析、科研辅助和结果展示，不替代森林草原防火主管部门、消防部门及其他政府部门发布的正式火灾统计、火灾认定或风险预警结果。

### 3. 支持的数据类型

V1.0 计划支持以下数据。

#### 3.1 FIRMS 主动火点数据

支持用户从 NASA FIRMS 等合法数据来源自行获取的主动火点 CSV 数据。

平台负责：

- 文件格式校验；
- 字段校验；
- 数据规范化；
- 质量筛选；
- 重复观测识别；
- 行政区域空间匹配；
- 时间统计；
- 区域统计；
- 地图展示；
- 结果导出；
- 数据来源与处理过程追溯。

平台统计结果表示满足处理规则的“主动火点观测记录”，不直接等同于实际独立火灾事件数量。

### 3.2 MCD64A1 火烧迹地数据

V1.0 主要处理由 MCD64A1 产品获得的 Burn Date 栅格以及与其对应的 QA 数据。

平台负责：

- 栅格文件校验；
- 坐标参考系统检查；
- Burn Date 数据解析；
- QA 数据检查与筛选；
- 烧毁像元识别；
- 火烧迹地面积估算；
- 行政区域空间统计；
- 时间统计；
- 地图展示；
- 结果导出；
- 数据和计算过程追溯。

平台计算得到的面积属于基于遥感栅格产品的估算结果，不等同于地面实测或主管部门最终核定的火灾过火面积。

### 4. 数据获取边界

V1.0 不负责替用户自动登录 NASA 或其他遥感数据网站下载数据。

用户负责按照数据提供机构的要求获取原始数据，并将受支持的数据文件提交至本软件。

软件负责对用户提交的数据执行后续检查、处理和分析。

### 5. 分析任务

平台以“分析任务”作为一次完整数据处理过程的基本业务单位。

每一个分析任务应具有唯一任务编号，并记录：

- 任务名称；
- 创建时间；
- 分析时间范围；
- 输入文件；
- 输入文件校验信息；
- 数据处理参数；
- 数据质量规则；
- 行政区划数据版本；
- 软件版本；
- 统计结果；
- 风险或关注等级计算结果；
- 输出成果；
- 运行状态；
- 错误和警告信息。

通过分析任务，可以对一次计算结果所使用的数据和参数进行追溯。

### 6. 统计功能

V1.0 计划提供以下统计能力：

- FIRMS 主动火点观测记录数量；
- MCD64A1 火烧迹地面积估算；
- 按日期统计；
- 按行政区域统计；
- 行政区域与时间联合统计；
- 数据质量筛选前后数量统计。

所有统计结果必须能够追溯至对应分析任务和输入数据。

### 7. 风险评价边界

平台风险评价分为两类。

#### 7.1 遥感火情相对关注等级

平台可以依据同一分析任务中不同区域的遥感火情指标，对区域进行相对比较。

该结果用于表示同一分析条件下不同区域之间的相对关注程度。

该结果不等同于政府部门发布的森林草原火险等级、火灾预警等级或其他法定风险等级。

#### 7.2 外部规则型风险评价

当用户提供具有明确来源的评价指标、阈值、权重及规则时，平台可以按照指定规则进行风险计算。

平台必须记录：

- 规则名称；
- 规则来源；
- 规则版本；
- 指标；
- 阈值；
- 权重；
- 适用范围；
- 计算时间。

未获得可靠规则来源时，不自行构造或宣称存在官方风险评价标准。

### 8. 空间分析范围

软件面向黑龙江省区域使用。

行政区域统计依赖用户或软件配置的行政区划矢量数据。

所有行政区域分析结果必须能够记录所采用的行政边界数据版本。

### 9. 可追溯性

平台应尽可能记录一次分析任务的完整计算链路，包括：

原始输入文件
→ 文件校验
→ 数据规范化
→ 质量筛选
→ 空间匹配
→ 统计计算
→ 风险评价
→ 地图与结果导出

输入文件应保存文件名称、文件大小、SHA256 等能够辅助识别数据版本的信息。

### 10. V1.0 不包含的功能

V1.0 暂不承诺实现：

- NASA 网站自动登录和自动下载；
- 实时卫星火灾预警；
- 火灾原因自动判断；
- 秸秆焚烧行为自动认定；
- 人工智能火灾识别模型；
- 火灾蔓延预测；
- 气象预报模型；
- 多用户互联网 SaaS 服务；
- 移动端 APP；
- 官方火灾事故认定；
- 官方森林草原火险等级发布。

后续版本如增加上述功能，应在完成真实实现、测试和资料依据确认后更新本文件。

### 11. 开发原则

本项目遵循以下原则：

1. 实际实现优先于界面展示；
2. 数据来源和处理方法可追溯；
3. 算法边界明确；
4. 不虚构数据、标准、指标或官方结论；
5. 每项正式功能应具有可执行代码；
6. 关键数据处理模块应具有测试；
7. 每个稳定开发阶段通过 Git 提交保存；
8. 文档、代码、界面和实际功能保持一致。
