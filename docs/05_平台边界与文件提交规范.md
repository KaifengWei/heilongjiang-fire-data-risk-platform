# 平台边界与文件提交规范（V1.0 需求基线）

## 1. 一句话定位

“黑龙江省火点数据检测与风险评估平台”是一套**官方遥感成果的自动化处理与解释平台**：用户自行下载原始数据，平台把这些专业文件转化为可核验的火点观测数量、火烧迹地面积、分区统计、专题地图、表格和规则型等级结果。

这里的“检测”是对官方火点记录和火烧迹地栅格进行读取、质量筛选、空间落区、统计与一致性检查；平台不从卫星原始辐射影像重新运行 NASA 的火点识别算法。

## 2. V1.0 的责任分界

### 用户负责

1. 从官方渠道下载与目标日期、目标区域相符的数据；
2. 至少提交一份主动火点文件和一份火烧迹地文件；
3. 确认数据时间、传感器、处理级别和下载来源；
4. 自定义范围分析时，提供有明确坐标系的合法行政区或研究区边界；
5. 若选择“规则型风险等级”，提供本单位认可的风险规则配置或明确选择平台的相对关注等级。

### 平台负责

1. 文件类型、字段、日期、坐标系、栅格波段和数值范围检查；
2. 保存文件哈希、来源说明、处理参数和运行日志；
3. 主动火点质量筛选、去重检查、行政区落点和观测记录计数；
4. Burn Date 重分类、无效值处理、栅格裁剪、面积计算和分区统计；
5. 按省、市、县或自定义区输出数量、面积和逐日/逐月变化；
6. 输出红色主动火点层、绿色火烧迹地层、风险/关注等级图；
7. 导出 CSV/XLSX、PNG、GeoPackage/GeoJSON、计算清单和处理报告；
8. 在数据不足、口径不一致或风险规则缺失时明确停止相应计算并说明原因。

### 平台不负责

1. 不把主动火点观测记录数解释为独立火灾事件数；
2. 不把 FIRMS 的 `scan × track` 观测足迹当作实际烧毁面积；
3. 不把 MCD64 烧毁像元数写成 FIRMS 官方火点数；
4. 不依据火点数据单独断言某点一定是秸秆焚烧；
5. 不把遥感估算结果表述为地面实测或执法认定；
6. 不在没有批准阈值、权重或相对比较样本时编造“高风险”；
7. V1.0 不替用户登录官网，不要求用户提交账号、密码或 MAP_KEY；
8. V1.0 不是实时预警、应急指挥或行政处罚系统。

## 3. 用户应提交的文件

### 3.1 必交文件 A：主动火点数据

**推荐格式：NASA FIRMS 直接下载的 CSV。**

支持的数据源范围：

- MODIS Collection 6.1；
- VIIRS 375 m / S-NPP；
- VIIRS 375 m / NOAA-20；
- VIIRS 375 m / NOAA-21。

最小必需字段：

| 字段 | 必需 | 用途 |
|---|---|---|
| `latitude` | 是 | 火点观测中心纬度 |
| `longitude` | 是 | 火点观测中心经度 |
| `acq_date` | 是 | 观测日期 |
| `acq_time` | 建议 | 卫星过境时间；用于更精确的时序与去重 |
| `instrument` | 建议 | 区分 MODIS/VIIRS 并选择对应质量规则 |
| `satellite` | 建议 | 区分 Terra、Aqua、S-NPP、NOAA-20、NOAA-21 |
| `confidence` | 建议 | 质量筛选和质量等级统计 |
| `frp` | 可选 | 火辐射功率；可参与强度分析，但不是面积 |
| `version` | 建议 | 记录 NRT/SP 和产品版本 |
| `daynight` | 可选 | 昼夜统计 |
| `scan`、`track` | 可选 | 描述观测像元尺寸；不用于计算实际烧毁面积 |
| `type` | 可选 | 仅在对应产品确实提供时用于热源类型辅助筛选 |

平台验收规则：

- 文件必须可解码为 CSV，表头不得完全缺失或手工改成无法识别的名称；
- 经纬度必须是有效数值，且目标分析为黑龙江时应落在边界或允许的外扩范围内；
- 日期必须能解析为 `YYYY-MM-DD`；
- 同一批可提交多个传感器 CSV，平台按“卫星—仪器—日期—时间—经纬度”形成去重键；
- NRT 和 SP 数据同时出现时必须保留版本来源，不能静默混合为一个未知口径。

官方 FIRMS 当前支持 CSV 主动火点下载，历史下载还可提供 Shapefile 和 JSON。V1.0 为降低字段截断、编码和多文件缺失风险，用户主入口只接收 CSV；SHP/JSON 作为后续兼容格式。

### 3.2 必交文件 B：火烧迹地数据

**V1.0 推荐格式：MCD64A1 Collection 6.1 月度 Burn Date GeoTIFF。**

推荐直接提交：

```text
MCD64monthly.AYYYYDDD.<区域或窗口>.061.burndate.tif
```

若下载目录同时提供质量层，建议一并提交：

```text
MCD64monthly.AYYYYDDD.<区域或窗口>.061.ba_qa.tif
```

平台验收规则：

- 必须是带坐标参考和地理变换的 GeoTIFF；
- 文件名或元数据必须能确定年份和月份；
- Burn Date 波段中 1–366 表示年积日，0 和负值按产品说明作为未燃烧或无效类别处理；
- QA 文件必须与 Burn Date 栅格的范围、分辨率、行列数和月份一致；
- 若缺少 QA，平台仍可计算产品标记的烧毁面积，但必须在结果中写明“未执行 QA 筛选”；
- 对多个窗口/瓦片，平台先做虚拟拼接或逐块统计，再按行政区去重，不能直接把重叠区域相加。

NASA FIRMS 的历史下载页面说明，MODIS/VIIRS 火烧迹地产品可从 University of Maryland 服务器获得 HDF、GeoTIFF 或 Shapefile。为保证首版流程直观、可用 GDAL/ArcGIS 检查，GeoTIFF 是用户提交的首选格式。

**HDF-EOS 边界：**Earthdata 原生 MCD64A1 常以 `.hdf` 瓦片提供，包含 `Burn Date` 和 `QA` 数据集。HDF 直读应作为 V1.0 的增强导入器单独实现和测试；在该导入器完成前，界面不能把 `.hdf` 标记为“已支持”。

### 3.3 平台内置文件：黑龙江行政区边界

正式版应内置一套经过人工核验的黑龙江省—市—县边界，并记录：

- 数据来源；
- 版本/年份；
- 坐标系；
- 文件 SHA-256；
- 是否经过拓扑修复和相邻区去重；
- 适用的行政区名称与代码。

用户无需为常规省、市、县查询重复提交边界。这样可避免不同用户使用不同边界造成统计不可比。

### 3.4 可选文件：自定义研究区

只在用户分析自定义范围时接收：

- `.geojson`；或
- `.zip`，其中包含完整 Shapefile 组件：`.shp`、`.shx`、`.dbf`、`.prj`，中文编码时建议附 `.cpg`。

无 `.prj`、几何无效、区域自相交或范围明显不在目标区的数据应被拒绝或进入“待修复”状态，不能默认猜测坐标系。

### 3.5 暂不作为统计输入的文件

以下材料可作为人工参考附件，但不能直接计算火点数量和面积：

- 官网截图、JPG/PNG 地图；
- PDF 报告；
- 手工抄录或二次汇总的 Excel 截图；
- 没有属性表的单独 `.shp`；
- 没有坐标系和像元含义说明的普通 TIF；
- WMS 地图截图或浏览器缓存图片。

## 4. 自动化处理流水线

```text
创建分析任务
  ↓
提交 FIRMS CSV + MCD64 Burn Date GeoTIFF（+ 可选 QA）
  ↓
文件哈希与格式校验
  ↓
读取日期、传感器、产品版本、坐标系和空间范围
  ↓
主动火点质量筛选 / 重复记录检查
  ↓
Burn Date 重分类 / QA 掩膜 / 无效值剔除
  ↓
统一坐标系与行政区裁剪
  ↓
火点观测记录计数 + 烧毁像元实际面积计算
  ↓
省—市—县分区统计 / 日月变化 / 传感器拆分
  ↓
相对关注等级或批准规则型风险等级
  ↓
专题地图、表格、GIS 图层、报告与计算清单导出
```

### 4.1 GDAL 与 ArcPy 的职责

**GDAL/OGR 是平台核心引擎：**负责 GeoTIFF/HDF 数据集读取、投影识别、重投影、裁剪、矢量几何、栅格化、拼接和格式导出。它能在没有商业 GIS 软件的机器上运行，适合开源仓库和软著复现。

**ArcPy 是可选兼容层：**当用户电脑已安装并授权 ArcGIS Desktop/Pro 时，可用于输出 File Geodatabase、调用 ArcGIS 专用制图模板或执行项目单位已有的 ArcPy 工具。平台不能捆绑 ArcPy，也不能把核心统计依赖于 ArcPy：

- ArcMap 10.x 通常绑定 Python 2.7；
- 当前平台使用 Python 3.11；
- ArcGIS Pro 的 ArcPy 运行环境与普通 Python 环境也需隔离。

因此，ArcPy 脚本应通过独立适配器调用，并与 GDAL 核心结果做一致性测试。没有 ArcGIS 许可证时，平台仍应能完成全部核心计算和常规输出。

## 5. 输出成果包

每个任务应生成一个独立目录或 ZIP，至少包括：

| 文件 | 内容 |
|---|---|
| `统计汇总.xlsx` / `.csv` | 按省、市、县的主动火点观测记录数、烧毁像元数、火烧迹地面积和等级 |
| `逐日逐区统计.csv` | 日期、区域、传感器、数量、面积、FRP 等可用指标 |
| `主动火点明细.csv` | 筛选后的原始字段、区域归属、质量标记和去重键 |
| `火烧迹地明细.csv` 或 GeoPackage | 像元/斑块日期、面积、区域、QA 信息 |
| `火点与火烧迹地分布图.png` | 行政区边界、主动火点层和火烧迹地层 |
| `关注等级或风险等级图.png` | 采用的模式、阈值和图例必须写在图中或报告中 |
| `process_manifest.json` | 输入文件名、SHA-256、处理时间、软件版本、参数、阈值、坐标系、错误与警告 |
| `处理说明.md` / `.pdf` | 数据口径、结果摘要、限制和不能作出的结论 |

## 6. 结果中的固定术语

| 推荐术语 | 禁止替换成 |
|---|---|
| 主动火点观测记录数 | 独立火灾数、实际着火次数 |
| 烧毁像元数 | 官方火点数 |
| 火烧迹地面积估算值 | FIRMS 火点面积、地面实测面积 |
| 遥感火情相对关注等级 | 官方灾害风险等级 |
| 规则型风险等级 | 无规则来源的“智能风险” |

## 7. 当前代码状态与 V1.0 缺口

| 能力 | 当前 v0.1 | V1.0 验收要求 |
|---|---|---|
| FIRMS CSV 导入、筛选和空间落区 | 已实现并用 61,698 条真实记录验证 | 增加浏览器上传、任务隔离和错误报告 |
| 已有烧毁像元明细导入 | 已实现并用 15,757 个像元验证 | 保留为历史成果兼容入口 |
| MCD64 Burn Date GeoTIFF 解析和面积计算 | 已实现；2026-03 原始 TIF 复现 1,140 个像元 | 补充多文件任务、QA 联合校验和性能优化 |
| HDF-EOS 直读 | 未实现 | 从 `Burn Date`/`QA` 子数据集读取并完成瓦片拼接测试 |
| 浏览器文件提交和任务进度 | 未实现 | 支持创建任务、上传、校验、处理、下载和失败重试 |
| 风险规则引擎 | 未实现 | 实现相对关注等级和配置型规则等级，保存规则版本与哈希 |
| XLSX、专题地图和完整结果包 | 部分能力已有旧工作流 | 整合到任务式统一导出 |
| ArcPy 适配器 | 未实现 | 作为可选模块，不影响 GDAL 主流程 |

这张表是软著材料的边界：只有“当前 v0.1”已实现的功能可以作为当前程序事实；V1.0 缺口完成并验收后，才能写进最终申请说明。
